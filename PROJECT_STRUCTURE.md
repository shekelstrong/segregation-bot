# Техническое описание заготовки

## 1. Назначение

Этот документ описывает текущее состояние репозитория до работы кандидата:

- какие файлы уже существуют;
- какой код уже работает;
- какие данные являются фиксированными;
- какие части нужно реализовать;
- как соединить предоставленные компоненты, не получая готового решения.

Полное задание и критерии приёмки находятся в [`README.md`](README.md).

## 2. Что представляет собой проект сейчас

Проект является неполной заготовкой. Он не запускается как Telegram-бот и не
умеет самостоятельно собрать итоговое видео.

Уже реализованы:

- строковый ключ режима;
- текст запроса двух строк;
- параметры видео и пути к ассетам;
- две анимационные фазы;
- низкоуровневые инструменты Pillow;
- кодирование последовательности кадров через `ffmpeg`;
- тесты предоставленных анимаций.

Не реализованы:

- точка входа бота;
- `Bot`, `Dispatcher`, `Router` и FSM;
- клавиатура с кнопкой;
- валидация пользовательского ввода;
- сборка четырёх визуальных состояний;
- расстановка текста;
- размещение header/footer;
- свайп между синей и розовой картами;
- статичные интервалы и общий порядок кадров;
- интеграция рендера с Telegram;
- управление временными файлами.

## 8. `animations.py`

Модуль содержит три публичные функции.

### `interpolate_positions(start, end, *, frame_count)`

Возвращает линейные целочисленные позиции.

```python
from segregation_video.animations import interpolate_positions

positions = interpolate_positions(1180, 0, frame_count=15)
```

Поведение:

- `frame_count <= 0` вызывает `ValueError`;
- `frame_count == 1` возвращает только `[start]`;
- при `frame_count >= 2` первая позиция равна `start`, последняя — `end`.

### `generate_transaction_slide_frames(...)`

```python
generate_transaction_slide_frames(
    current_screen,
    transaction_screen,
    frame_count=15,
)
```

Требования:

- оба изображения должны иметь одинаковый размер;
- `current_screen` должен быть полностью собранной розовой карточной сценой;
- `transaction_screen` должен уже содержать имя, номер и комиссию;
- первый кадр совпадает с `current_screen`;
- последний кадр совпадает с `transaction_screen`;
- экран транзакции движется справа налево.

Функция возвращает ленивый итератор Pillow-кадров.

### `generate_details_slide_frames(...)`

```python
generate_details_slide_frames(
    transaction_screen,
    details_screen,
    details_height=1982,
    frame_count=20,
)
```

Требования:

- `transaction_screen` должен быть полностью собран;
- `details_screen` должен уже содержать все значения блока деталей;
- высота деталей должна быть от `1` до высоты основного экрана;
- блок масштабируется пропорционально;
- первый кадр ещё не показывает блок;
- последний кадр прижимает блок к нижней границе;
- движение идёт снизу вверх.

Входные изображения функции не закрывают. Каждый полученный кадр обязан закрыть
потребитель либо `iter_encode_visually_lossless_from_pil(...)`.

### Чего в модуле нет

Модуль не содержит:

- свайп Mastercard → Visa;
- статичные интервалы;
- header/footer-композицию;
- построение экранов;
- полный порядок фаз;
- MP4-кодирование.

## 10. `_util/video/render_video_from_frames.py`

### `encode_visually_lossless_from_pil(...)`

Принимает список Pillow-изображений. Все кадры одновременно находятся в памяти,
поэтому для полного видео этот вариант менее предпочтителен.

### `iter_encode_visually_lossless_from_pil(...)`

Принимает любой iterable или генератор и передаёт RGB-байты в `ffmpeg` через
stdin. Для данного задания это предпочтительный вариант, поскольку он не требует
хранить сотни полноразмерных кадров.

Пример финального вызова:

```python
iter_encode_visually_lossless_from_pil(
    frames=build_complete_timeline(),
    output_file=str(output_path),
    framerate=60,
    crf=12,
    preset="fast",
)
```

`build_complete_timeline()` в заготовке отсутствует и должен быть реализован
кандидатом.

Ограничения текущего кодировщика:

- команда `ffmpeg` должна быть установлена отдельно;
- используется `libx264`;
- все кадры должны иметь одинаковый размер;
- пустая последовательность вызывает ошибку;
- выходной файл перезаписывается;
- stdout и stderr `ffmpeg` скрыты;
- готовой отмены процесса нет;
- готовой генерации уникальных путей нет.

Кандидат отвечает за корректное завершение процесса и очистку результата при
ошибке.

from _pillow.text_draw import execute as draw_text

- не подключать helper только ради одного неиспользуемого вызова;
- проверять docstring выбранной функции.

## 12. Рекомендуемый поток данных

```text
Telegram message
    -> parser and validator
    -> client_name + client_number
    -> build Mastercard state
    -> candidate Mastercard-to-Visa swipe
    -> build Visa state
    -> provided transaction slide
    -> build transaction state
    -> provided details slide
    -> complete frame iterator
    -> ffmpeg encoder
    -> unique temporary MP4
    -> Telegram response
    -> cleanup
```

Экран сначала должен быть полностью собран, и только затем передан в генератор
анимации. Telegram-объекты не должны попадать в функции пиксельной отрисовки.

Пример возможного разбиения:

```text
segregation_video/
├── router.py       # кнопка, handlers и FSM
├── states.py       # состояния диалога
├── validation.py   # разбор двух строк
├── screens.py      # четыре готовых визуальных состояния
├── swipe.py        # самостоятельный свайп карт
├── timeline.py     # статичные кадры и объединение фаз
├── service.py      # временный файл и запуск рендера
└── constants.py    # параметры и фиксированные данные
```

Это рекомендация, а не обязательные имена файлов.

## 14. Практические ограничения

### Память

Один RGB-кадр `1180 x 2556` занимает около `8.6 MiB` без накладных расходов.
Список из сотен кадров может занять несколько гигабайт. Предпочтителен ленивый
генератор.

### Event loop

Pillow и `ffmpeg` выполняют синхронную работу. Их прямой вызов внутри async
handler блокирует обработку других сообщений.

### Параллельность

Нельзя использовать общий путь вроде `output/result.mp4`. Подойдут `tempfile`,
UUID или отдельный идентификатор задания.

### Диагностика

Текущий кодировщик скрывает stderr `ffmpeg`. Для понятной диагностики кандидат
может изменить эту часть, сохранив интерфейс или обосновав новый.
